# Classroom example: fictional product-page preview

The exercise ends at a reviewed **preview**, not a real publication. No customer data, real account, or credential is used.

1. Coordinator records a goal, observable criteria (factual price/claims, 320px layout, working preview links), a sourceRef and separate requestDedupKey. Publishing requires later human approval and is outside the exercise.
2. Research A verifies fictional product facts and submits facts-v1. An independent reviewer records criterion results and accepts that version.
3. Writing B and design C can start in parallel, each consuming accepted A v1. Temporary OpenClaw children, if available, are execution attempts linked by verified IDs; they do not become permanent owners.
4. Builder D starts only after current B and C artifacts pass review. QA E tests D's preview independently.
5. If QA finds a fictional 28,000/29,000 price conflict, B submits v2. Affected D and E evidence becomes stale. Rebuild and re-review affected descendants; do not erase the old attempts.
6. Coordinator integrates accepted current versions, checks the complete preview, and records an integration seal. State remains awaiting approval; there is no delivery receipt and no claim of live publication.

See the repository's JSON snapshots and validator for a checkable run. In a copied skill folder this example remains readable without repository files.
