# Classroom example: publish a product page

Goal: publish an accurate mobile-ready product page after human approval.

1. Coordinator defines price accuracy, evidence for claims, mobile display, and owner approval as completion criteria.
2. Researcher A collects verified product facts.
3. Writer B and designer C work in parallel only after A's evidence is accepted.
4. Builder D assembles the page after B and C pass review.
5. Independent reviewer E checks price, claims, mobile behavior, and links.
6. Coordinator integrates the approved artifacts, shows a concrete preview, obtains the required publishing approval, publishes, and verifies the live URL.

If E finds an unsupported price claim, B revises it. D's build and E's prior check become stale until the revised copy is integrated and rechecked. A task card marked “done” does not bypass that gate.

Explain the diagram as **intake → verified research → parallel writing/design → build → independent QA → coordinator integration → approved release**. Show task owner, evidence, blocker, and next action at each node. Use fictional product data and placeholder account IDs in public materials.
