# 수강생 교안 · 범용 오케스트레이션

## 목표와 준비

90분 실습. 가상 상품 상세페이지의 **미리보기**를 만들며 실제 게시·결제·고객 데이터·토큰은 사용하지 않는다. 오프라인 경로는 텍스트 편집기·Node.js·브라우저로 충분하다. OpenClaw 연동 경로에서만 [README](../README.md)의 스킬 설치와 새 세션 인식을 검증한다.

학습 결과: Run/Task/Execution/Artifact/Review/Integration/Approval/Delivery를 구분하고, DAG와 독립 QA를 운영하며, 임시 자식 세션의 흔적을 정확한 작업에 연결하거나 미연결로 보존한다.

## 1. 수동 원장 (20분)

가상 요청: ‘가격 근거와 320px 가독성이 확인된 상품 상세페이지 미리보기.’ 출처와 별개의 요청 멱등키, 세 가지 관찰 가능한 기준, 게시 금지/승인 경계를 적는다. A 조사 → B 문구와 C 디자인 병렬 → D 조립 → E 독립 점검 → 코디네이터 통합 DAG를 그린다. 각 작업에 한 책임자, 입력 버전, 산출물, 검수자, 의존성을 적는다.

## 2. 실제 위임과 임시 자식 (15분)

작업 카드 생성은 위임이 아니다. ‘요청 → 접수증 → 시작 → 종료 → 결과 수집’을 각각 표시한다. OpenClaw가 있으면 가상 자료만 사용해 두 자식을 실행하고 서로 다른 세션 키, 부모 키, 연결된 작업 ID를 기록한다. 없으면 [시나리오 JSON](../examples/product-page/scenario.json)의 B/C 실행을 읽는다. 자식의 성공 종료만으로 B/C를 accepted로 바꾸지 않는다. 연결 근거가 없으면 unlinked로 둔다.

## 3. QA와 재작업 (20분)

A의 검수 근거를 확인하고 B/C를 시작한다. B v1은 처음에 독립 검수를 통과해 D가 조립했지만, E의 후속 점검에서 28,000원/29,000원 충돌이 발견된다. B v1의 합격 판정을 철회·반려하고, 이를 쓴 D/E 기록을 stale로 보존한다. B v2 제출 후 영향받은 작업을 다시 만들고 버전별 근거로 재검수한다. 검수자가 생산자와 같은 경우 독립 QA가 아니다.

## 4. 통합과 승인 경계 (15분)

현재 accepted 버전만 통합하고 가격/모바일/링크의 전체 증거를 기록한다. 수업은 ‘승인 대기’에서 끝난다. 실제 게시, live URL, 전달 완료 영수증은 없다. [데모](../dashboard/demo.html)에서 세 스냅샷을 전환하고 동일한 JSON을 확인한다.

## 5. 검증과 토론 (20분)

저장소 루트에서:
- node scripts/validate-run.mjs examples/product-page/sample-run.json examples/product-page/scenario.json
- node --test scripts/validate-run.test.mjs dashboard/flow-model.test.mjs
- python3 -m http.server 8765 (별도 터미널), 브라우저에서 http://localhost:8765/dashboard/demo.html

토론: 중복 이벤트는? 부모가 먼저 끝나면? 외부 게시 요청이 타임아웃되면? 정답은 각각 멱등 처리, 자식 기록 재조정, 실제 게시/영수증 확인 전 재시도 금지다.

## 평가(100점)

목표·검증 가능 기준 15, 역할/권한 15, DAG·병렬·차단 20, 산출물 버전과 독립 QA 증거 20, 반려 후 영향/재검증 15, 통합·승인·전달의 구분 15. 단순 done이나 세션 성공을 검수 통과로 표시하면 수정 제출 대상이다.

## 강사용 설명

수동 실습에서 자동 DAG 잠금을 주장하지 않는다. 임시 세션의 실제 추적은 어댑터 모드/버전별로 확인한다. 대시보드는 화면 예시이지 운영 API가 아니다. 학생이 실제 운영 자동화를 만들려면 [계약](../skill/agent-orchestration/references/contract.md)의 권한·원자성·복구를 별도로 구현/검증해야 한다.
