# 수강생 교안 · 팀으로 한 건 끝내기 (90분)

> 대상: 1주차에 팀(총괄 + 전문가 1~3명)과 대시보드를 만든 수강생. 용어는 최소로. 엄밀한 정의가 필요하면 [계약 문서](../skill/agent-orchestration/references/contract.md)를 본다.

## 오늘 배우는 것 (한 문장)

**"에이전트 여러 명을 썼다"가 아니라 "누가 뭘 만들었고, 누가 확인했고, 뭐가 바뀌어서 뭘 다시 했고, 진짜 나갔는지"가 남게 일하는 법.**

준비물: 1주차 팀(`team.md`), 오케스트레이션 스킬 설치(`openclaw skills list` 에 `agent-orchestration`), 실습 주제 하나(기본: 블로그 글 1편 — [예제](../examples/blog-post/README.md)). 실제 발행·발송·결제·고객 데이터는 쓰지 않는다.

## 흐름

| 시간 | 단계 | 수강생이 하는 일 | 강사가 보는 것 |
|---|---|---|---|
| 0–15 | **개념** | 그림 한 장(총괄→전문가→독립 검수→통합→전달 확인) · 용어 10개 | "검수자 ≠ 담당" 과 "통합 ≠ 발행" 두 문장을 따라 말할 수 있는가 |
| 15–35 | **원장 만들기** | 총괄 에이전트에게 Lite 모드 요청 → 원장(표 1장) 받기 → 완료 기준 2~4개·담당·선행·검수자 확인 | 완료 기준이 "눈으로 확인 가능"한가. 검수자가 담당과 다른가 |
| 35–55 | **실행과 제출** | A 시작 → 통과 → B·C 동시 시작 → 제출물에 v1 붙이기 → 검수 요청 | 하류가 상류 통과 **전에** 시작하지 않았는가. 세션 ID 가 실행 기록에 있는가(없으면 "수동 시작") |
| 55–70 | **반려 1회** | 검수가 결함을 찾는다(없으면 일부러 링크 하나 깨기) → 반려 → 새 버전 → 그걸 쓴 하류 stale → 다시 | 옛 기록을 **지우지 않고** 남겼는가. 새 버전으로 재검수했는가 |
| 70–80 | **통합** | 총괄이 합치고 완료 기준 3개 전체 점검 → "승인 대기" | 통합에 쓴 버전이 전부 "현재 통과" 버전인가 |
| 80–90 | **회고** | 원장 1장 캡처 + "반려된 것·고친 것" 1문장 → 베이스캠프 모닥불 | — |

## 채팅에 보낼 문장 (복사용)

```
이 목표를 agent-orchestration 스킬의 Lite 모드로 진행해줘.
목표: 블로그 글 1편을 발행 직전까지
완료 기준: (1) 모든 인용에 열리는 출처 링크 (2) 이미지 3장 1200px 깨짐 없음 (3) 에디터 미리보기 순서 확인
팀: 조사=리서처, 글=글벗, 이미지=디자이너, 검수=QA, 조립=총괄
원장(ledger-template)을 만들어 작업표를 보여주고, 시작 전에 내 확인을 받아줘. 발행은 내가 직접 한다.
```

## 자주 나오는 실수 → 어떻게 고치나

| 실수 | 왜 문제인가 | 고치는 말 |
|---|---|---|
| 작업 카드만 만들고 "시작했다" | 카드는 계획이지 실행이 아니다 | "담당이 실제로 시작했는지 세션 ID 로 확인해줘" |
| 세션이 끝났으니 "제출됐다" | 끝난 것과 결과물이 있는 것은 다르다 | "산출물 버전과 위치를 적어줘" |
| 만든 에이전트가 자기 것을 검수 | 독립 검수가 아니다 | "검수자를 다른 에이전트로 바꾸거나 '독립 검수 아님'이라고 적어줘" |
| 반려 뒤 하류를 그대로 통합 | 낡은 입력으로 합친 것 | "B 가 바뀌었으니 D·E 를 stale 로 표시하고 다시 만들어줘" |
| "발행 완료"인데 URL 이 없다 | 영수증 없는 전달은 전달이 아니다 | "실제 URL 을 확인하기 전까지 승인 대기로 둬" |

## 평가 (100점)

| 항목 | 점수 | 무엇을 보면 되나 |
|---|---|---|
| 목표·완료 기준 | 15 | 기준 2~4개가 "내가 눈으로 확인" 가능한 문장인가 |
| 역할·검수자 분리 | 15 | 작업표에서 검수자 ≠ 담당. 겸임이면 명시했는가 |
| 선행 관계·병렬·대기 | 20 | 하류가 상류 통과 뒤 시작. B·C 병렬. 막힘에 이유·재개 조건 |
| 버전과 독립 검수 증거 | 20 | 제출물마다 v번호. 검수 결과가 기준별 + 근거 위치 + 시각 |
| 반려 후 무효화·재검수 | 15 | stale 표시, 옛 기록 보존, 새 버전 재검수 |
| 통합·승인·전달 구분 | 15 | 통합 완료 ≠ 승인 ≠ 전달. 영수증 없이 "전달 완료" 쓰면 0점 |

세션 성공이나 단순 `done` 을 검수 통과로 적은 과제는 수정 제출.

## 강사 메모

- Lite 모드는 **원장 1장**이 전부다. JSON 검증기·대시보드 데모는 "더 알고 싶은 사람" 용(`node scripts/validate-run.mjs examples/blog-post/scenario.json`, `python3 -m http.server 8765` → `dashboard/demo.html`).
- 임시 서브에이전트 추적은 OpenClaw 버전마다 다르다. 세션 ID 가 안 보이면 "수동 시작"으로 적게 하고, 자동 추적이 된다고 말하지 않는다.
- 수강생이 실제 운영 자동화(자동 배정·게이트)를 만들고 싶어 하면 [계약](../skill/agent-orchestration/references/contract.md)의 권한·원자성·복구를 별도로 구현·검증해야 한다고 안내한다.
