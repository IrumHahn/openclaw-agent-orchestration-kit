# 임시·중첩 서브에이전트 실행

배포 스킬만 설치해도 읽을 수 있는 정본은 [runtime.md](../skill/agent-orchestration/references/runtime.md)다. 이 문서는 수강생이 어댑터를 설계할 때 사용할 질문을 보충한다.

- **사전 래퍼/훅 모드:** 실행 의도를 기록한 후 spawn한다. 접수증·시작·종료·결과 이벤트가 실제 버전에서 보이는지 테스트한다.
- **수동 접수증 모드:** 총괄이 검증된 자식 세션 키와 부모·작업 링크를 직접 기록한다. 자동 완전성은 주장하지 않는다.
- **사후 관찰 모드:** 세션 기록에서 수집한 흔적은 부분적이다. 작업과 연결할 검증 근거가 없으면 미연결로 둔다.
- **식별 불가:** 실행 사실만 수동 기록하고 추적 불가를 명시한다.

같은 부모에서 나온 두 자식은 다른 Execution ID와 확인된 런타임 키를 가진다. 늦은 완료 이벤트, 중복 훅, 부모보다 늦게 끝나는 자식, 취소, 실패, 재시작을 별개 이벤트로 보존한다. 임시 세션이 사라져도 원장의 출처·시각·결과·원본 참조는 남는다. 성공 종료는 QA 합격이 아니며 부작용이 불확실하면 실제 상태를 조회하기 전 재시도하지 않는다.

구현 전 질문: 이벤트 접근권한이 있는가? 보존 기간은? 훅 실패를 어떻게 감지하는가? 개인정보/프롬프트를 저장하지 않고 필요한 증거만 남길 수 있는가? 수동 링크를 누가 어떤 근거로 승인하는가? 대시보드는 원장을 읽는가, 추측하는가?
