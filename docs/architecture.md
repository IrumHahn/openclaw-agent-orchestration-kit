# 범용 에이전트 오케스트레이션 설계

이 문서는 제품 독립적 계약이다. 스킬 설치만으로 서버·자동 배정·훅·승인 서비스가 생기지 않는다. 실제 환경에 존재하는 기능을 먼저 조사하고 **설계 / 수동 운영 / 계측 운영 / 감사** 모드를 명시한다. 자세한 필드와 불변식은 [스킬 내 계약](../skill/agent-orchestration/references/contract.md)을 따른다.

## 책임의 경계

사용자 의도 → 코디네이터의 Run → 의존성 있는 Task → 실제 Execution → 버전 고정 Artifact → 독립 Review → Integration → 필요한 Approval → 검증된 Delivery. 임시 서브에이전트는 Execution이며 Task의 책임자를 대체하지 않는다. 성공 종료는 산출물 제출도 검수 통과도 아니다.

## 도입 순서

1. **수동 원장:** 프로젝트/Run ID, 출처와 별개인 멱등키, 작업 ID, 기준·의존성·책임자를 기록한다. 선행 검수 전 하류 작업을 사람이 보류한다.
2. **실제 위임 증거:** 디스패치 요청/접수/시작/종료/결과를 구분하고 세션·런타임 ID를 Task에 연결한다. 직접 연결 불확실한 자식은 미연결로 보존한다.
3. **독립 검수와 무효화:** 정확한 산출물 버전에 판정·기준별 증거·검수자·시각을 붙인다. 상류 버전이 변하면 영향 받은 하류와 통합을 stale로 만든다.
4. **선택적 화면:** 권위 저장소의 투영만 읽는다. 데이터가 없는 의존성이나 합격은 만들지 않는다. 단순 문자열 상태는 확인 전 ‘기록된 주장’으로 표시한다.
5. **자동 제어면:** 필요할 때만 서버 전이, compare-and-swap, 이벤트 중복 제거, 내구성 있는 아웃박스와 재조정을 붙인다. 기존 작업방과 이중 권위를 만들지 않는다.

## 필수 결정

- 권위 저장소/백업/보존 기간 및 비밀정보 제외 범위
- 런타임별 자식 세션 이벤트 가용성 및 누락 시 재조정 방식
- 외부 발송·게시·구매의 승인자, 멱등키, 실제 전달 영수증
- 검수 독립성, 자격/권한 검증, 기준별 근거
- 장애 시 재시도 소유자 및 ‘부작용 발생 여부 불명’ 상태 처리

## 수용 기준

샘플 JSON 검증, 복사 설치 링크 검사, 중복/늦은 이벤트와 부모 종료 후 자식 확인, 상류 변경 시 무효화, 독립 검수 없는 통합 거부, 전달 영수증 없는 완료 거부를 증명한다. 제공된 검증기는 교육용 스냅샷의 구조·일부 불변식을 검사할 뿐, 운영 저장소의 인증·원자성·이벤트 처리를 대신하지 않는다.
